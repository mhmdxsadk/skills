# Technical design

Use the relevant fields below; reference existing material.

## Drivers and constraints

Link or summarize the requirements and workflows that shape the design. Capture existing technology, user preferences, platform, budget, maintenance capacity, and consequential quality constraints. Keep future ambitions separate from current requirements.

## Recommended approach and decisions

Describe the proposed stack and why it fits. For material choices, record credible alternatives, tradeoffs, decision authority, and what would justify revisiting the choice. Include sources and dates for current claims; state assumptions behind cost estimates.

## Components and data flow

Describe responsibilities, execution locations, and how components communicate through the core workflows. Add a diagram when helpful. Connect the design to the requirements it supports.

## Data and access

Describe core entities and relationships, ownership, storage, and relevant lifecycle rules. Explain identity and permission boundaries where needed.

## Integrations and operation

Specify external dependencies and relevant inputs, outputs, processing states, and failure handling. Capture hosting or distribution, secrets handling, and proportionate recovery and diagnostic needs.

## Uncertainty and readiness

Record unresolved choices, existing evidence, proposed checks, and dependent decisions or tasks. Distinguish deferred risks from blockers. Note any agreed changes to requirements and which work can proceed to implementation planning.
